Two ways to open your dashboard. Everything is read-only — balances and history only.

🛡 Why entering a seed here is safe (verify yourself)
  • The seed never crosses the network. Derivation runs in your browser with the SDK bundled below (/vendor/keetanet-browser.js — self-hosted, no CDN). Only derived public keeta_… addresses are sent to the server. Check it live: open DevTools → Network while deriving.
  • The seed is never stored. Not localStorage, not cookies, not the server — it exists in memory for the single operation, then it's gone. Closing the tab erases it.
  • The server can't leak what it never has. DashKee's backend runs on a throwaway random key with read-only calls; there is no seed database to breach.
  • Injected code can't run. A strict Content-Security-Policy allows only this site's own scripts — no inline or third-party script could ever read what you type.
  • Auditable. The whole client is open source — read the derive + banking flow before trusting it.

🔒 Watch an address

Paste any Keeta address (or several, one per line). Nothing sensitive required.

🔑 Unlock with seed (advanced)

Only if you need to discover subaccounts you can't name. Derivation happens inside your browser — the seed is never sent or stored. Even so, only paste a seed you'd be comfortable having typed on this device; prefer a watch-only setup whenever you already know the addresses. Paste a seed you'd use for real funds at your own risk.

Your seed is processed locally with the official Keeta SDK (self-hosted). Only public keeta_… addresses are ever transmitted. Saved addresses live in your browser's localStorage.

💡 Why do I see storage accounts I never opened? An ACL entry only means your account has been granted a permission on that storage account — not that you created it. Token issuers and anchors (e.g. the USD/EUR stablecoins) create storage accounts to hold your token balances and grant your account access. DashKee checks the OWNER flag of each one, so you can see exactly which are yours.
